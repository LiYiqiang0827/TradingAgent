# 默认无外部 Agent 的复盘交接

## 1. 决策

日常 A 股日复盘和周复盘采用一条责任链：

```text
确定性接口与校验 -> 压缩事实包 -> 定向催化搜索 -> GPT/Codex 直接分析与写作
                     -> 确定性验收 -> 固定 XeLaTeX PDF
```

默认不调用 GLM、Hermes、Gemini 或其他外部写作/审核 Agent。原因不是外部模型永远无用，而是每日复盘的核心成本在事实压缩、冲突处理和结构判断；把已压缩事实交给另一个模型写初稿后，GPT/Codex 仍需逐项核对，协调成本超过了可确认的节省。

外部模型仅保留为例外工具：策略或风控规则发生重大变化、真实重大交易决策、确定性证据无法解决的数据冲突，或 GPT/Codex 明确低置信度。任何外部输出均为未验证草稿，不能进入最终报告而跳过 Codex 验收。

## 2. 2026-09-22 运行的证据

当次产物大小如下；它们只能作为上下文规模的代理，不等于模型账单中的精确 token：

| 产物 | 字节数 | 含义 |
|---|---:|---|
| `MR_PACKET.json` | 139,502 | 完整事实包 |
| 压缩写作包 | 24,701 | 较完整事实包减少约 82.3% |
| `CATALYSTS.json` | 2,425 | 定向联网研究 |
| GLM 初稿 | 7,378 | 未验证草稿 |
| 最终报告 | 15,778 | Codex 修正和重写后的文本 |

结论：接口和压缩程序明确节省上下文；GLM 没有显示出可验证的净节省。最终报告不仅需要复核，而且相对初稿发生了大量实质修订。该次运行没有记录逐调用 token，因此不得宣称精确节省比例。以后若需要评估成本，应按“事实包构建、催化搜索、写作、返工、PDF”分阶段记录模型输入/输出 token 和耗时。

## 3. GLM 初稿暴露的问题

这些不是措辞偏好，而是会改变交易判断的错误：

1. 把华天科技写成“缩量回调”，但当日成交量/成交额口径约为启动日的 1.17 倍，方向相反。
2. 把“数据缺失或未进入领先集合”写成“零涨停、零成交占比”。缺失不能改写成零。
3. 候选排序偏离形态契约：初稿抬高华天科技、通宇通讯、中材科技；修正后的观察池是格尔软件、科森科技、共进股份，严格候选仍为空。
4. 对智能驾驶、MR、数据要素的封板质量和资金迁移下了过强结论，超过数据包能支持的范围。
5. 把叙事流畅度当成事实确定性。复盘最需要的是证据边界和空仓纪律，不是自动补齐故事。

因此，不能用“让外部模型写、Codex 快速抽查”作为默认流程。真正可靠的抽查需要回到原始证据，等同于重新做关键分析。

## 4. 已纠正或固化的平台问题

### 4.1 涨停状态不是单源真相

开盘啦涨停/炸板列表必须与收盘价和每日涨跌停价复核。2026-09-22 共检查 83 个事件，发现并修正 1 个冲突：瑞芯微被来源列表标为炸板，但收盘价等于涨停价，应归为收盘涨停。修正记录必须进入 `DATA_QUALITY.json`。

### 4.2 连续板与 N 天 M 板分账

标签缺失时，不能把来源中的数字字段直接当连续板。必须根据逐日涨停历史重建连续性；非连续再板进入 N 天 M 板，不进入最高板梯队。

### 4.3 两种“封板率”不能混用

- 板块收盘封板率 = 板块收盘涨停数 / 合格板块成员数。
- 触板封住率 = 收盘涨停数 /（收盘涨停数 + 触板未封数）。

前者是用户指定的板块宽度口径，后者只描述触板后的封住质量。报告必须标明使用哪一种。

### 4.4 时间字段必须承认不可得

当 KPL 当日明细缺失时，首次触板、最终封板、开板次数和一字板顺序可能不可靠。最终封板时间不得用首次触板时间代替。没有经验证的分钟数据时，14:30 后炸板数量写“不可用”，不能写 0。

### 4.5 缺失、未入榜与零严格分开

题材没有进入领先集合，不等于题材当日涨停数为零；字段不可得，也不等于数值为零。程序负责保留空值和数据质量状态，模型负责在文字中明确边界。

### 4.6 资金迁移不用“主力净流入”背书

资金流向字段可能受供应商算法、分类重叠和成交归因影响。日常结论以指数和宽度、成交额与题材成交占比、涨停梯队、晋级/断板、容量核心和后排同步性为证据。只要不存在可靠且定义清楚的唯一答案，就不把净流入值写成权威事实。

### 4.7 候选池按时间语义分开

- `first_pullback_in_progress`：首次回调仍在进行，可作前置观察。
- `restart_completed_samples`：当日已经完成再启，只作样本或延续观察。
- `continuous_board_relay`：连续板接力，不冒充首次回调。
- `new_launches_for_future_tracking`：今日新启动，等待后续回调。

active free float 不进入全市场主流程，只在最终极少数候选确有必要时补查。

### 4.8 point-in-time 纪律

同一股票可以在多个开盘啦题材重复计数，但不能用后来更新的标签改写历史交易日。历史复盘只使用当时可得快照；题材重叠由 GPT/Codex 判断当天主要带动关系。

## 5. GPT/Codex 不可替代的增值

接口负责事实，不负责以下结论：

- 首日涨停潮是主线、候选还是一日游；
- 高标晋级和中位股掉队是否形成真实亏钱效应；
- 旧方向退出后，新方向是承接、轮动还是日内高潮；
- 多题材重叠股票当天实际带动哪个方向；
- 好股票、好形态和次日可交易买点是否同时成立；
- 催化发生时间是否能解释股价启动；
- 没有合格机会时是否应明确空仓。

这部分由 GPT/Codex 直接完成，避免把同一推理先交给外部模型生成，再重复复核。

## 6. 联网搜索边界

事实包已通过校验后，不再联网复查指数、成交额、涨停数量、梯队、晋级率、题材统计、个股当日价格或成交。联网仅用于：

- 政策、会议、产业事件；
- 公司公告、澄清公告和重大风险；
- 最终少量候选的数据包外业务背景；
- 数据源冲突无法由本地确定性证据解决的例外情况。

这条边界同时服务可靠性和 token 节省：同一行情事实只建立一次权威口径。

## 7. 固定 LaTeX/PDF 交付

使用 MiKTeX 的 XeLaTeX 编译 `latex/market_review_template.tex`。模板固定 A4、深蓝/金色体系、页眉页脚、章节层级、表格和引用框，并对章节与表格分页做保护。仓库只保存模板，不保存 MiKTeX、宏包缓存、生成 PDF 或额外 PDF 软件。

参考运行中，2026-09-22 报告生成 6 页 A4 PDF；链接、中文字体、页码、表格、标题均通过页面渲染检查，未发现空白页、溢出、缺字或 LaTeX 错误。首次安装 MiKTeX/宏包可能较慢；环境就绪后的典型编译约 3 秒，连同页面验收约 5 秒。

PDF 只从已经验收的 Markdown 生成，不在 LaTeX 阶段改写事实。若编译日志出现 `Overfull` 或 `Missing character`，应视为版式验收失败。

## 8. 新 AI 的执行顺序

1. 读取 `toolbox_manifest.json`、本文、`AI_CONTRACT.md` 和 `REPORT_CONTRACT.md`。
2. 运行 `build_review_packet.py`，只在显式要求时使用 `--refresh`。
3. 要求 `PACKET_VALIDATION.json.status == PASS` 且 `DATA_QUALITY.json.required_missing` 为空。
4. 只对催化和候选背景做定向联网搜索，写入 `CATALYSTS.json`。
5. 运行 `build_context_packet.py` 生成 `CONTEXT_PACKET.json`。
6. GPT/Codex 直接写作，必要时回读完整 `MR_PACKET.json`，不得让外部模型替代核心判断。
7. 运行 `finalize_review_run.py --codex-reviewed`。
8. 仅在验收通过后把报告填入模板，用 MiKTeX/XeLaTeX 编译，并检查日志与渲染页面。

旧的 `build_agent_packet.py`、GLM schema 和示例为兼容历史运行而保留，不属于默认流程。
