## 0. 阅读说明

本文档按 **固定编号** 给出每个数据集的 8 个栏目:

1. **内容与来源**
2. **实际存量**
3. **采集范围**
4. **字段含义**
5. **时间含义**
6. **获取能力**
7. **质量与缺口**
8. **交付情况**

> 三个栏目独立说明、避免"可用"二合一带过:
> - **实际存量**:DB/表/记录数/起止日期(本次实查)
> - **接口实际验证情况**:是否能拿到、补历史最远到哪、限频(本次实查 + 接口文档)
> - **数据质量验收情况**:做了哪些字段检查 / 通过 / 失败 / 未做

**编号体系**:`A` = 离线日终数据;`B` = 实时/盘中数据;`C` = 开盘啦(kpl)原生 HTTP API;`D` = 上层统一数据接入层(`coreClient/data_provider.py`);`E` = 调度/服务。

## 2. 开盘啦(kpl)相关数据集(逐项)

### A01 · KPL 当日涨停表现详情(`tbl_cn_kpl_limit_performance`)

1. **内容与来源**:开盘啦"涨停表现"详单(逐股:封板时间、炸板次数、涨停原因、题材归属、主力资金、流通市值等)。提供方:同花顺 KPL 后端 `apphwhq.longhuvip.com`,接口 `HomeDingPan/GetDailyLimitPerformance`(实时)+ `HisHomeDingPan/GetDailyLimitPerformance`(历史)。
2. **实际存量**:`offlineDataManager/data/db_cn_kpl.db → tbl_cn_kpl_limit_performance`。**328,406 行,起 2024-04-20,止 2026-09-18,日频,全市场 A 股**(部分 B 股 / 北交所 920 也有)。板型分布:2026-09-18 当日一板 66、二板 8、三板 2、四板 2。
3. **采集范围**:**当日最终涨停名单**(不包含当天曾涨停但最终未封住的票——这些只会在 `tbl_cn_kpl_list` 的 tag='炸板' 里)。
4. **字段含义**:`trade_date / ts_code / name / board_type(1/2/3/4/5=一/二/三/四/更高板)/ board_count(连板数)/ lu_time(unix 17 位毫秒?实测样例 1789713208 转北京时间正常)/ theme / theme_id(同花顺行业代码 801xxx)/ sector_id / limit_reason(涨停原因)/ is_break(是否炸板过)/ amplitude(振幅%)/ turnover_rate(换手率%)/ limit_order(封单金额)/ lu_limit_order(封板时涨停封单)/ net_change / main_in / main_out / amount / free_float / close_price / pct_chg / snap_ts`。单位:金额=元、振幅/换手率/涨幅=百分比。
5. **时间含义**:`trade_date`=交易日期;`lu_time`=首次封板时间(Unix timestamp);`snap_ts`=采集入库时间。**该表是当日封板后定时落盘,因此历史查询返回的是"当时落盘版本",后续该日若有复盘更新不会回写**(KPL 历史版同一接口路径 `HisHomeDingPan/GetDailyLimitPerformance`)。
6. **获取能力**:可补任意交易日(API 接受 `Day=YYYY-MM-DD`)。最早 2024-04-20 起。节流 ≥1s/请求(README 默认),kpl-api 已实测 21 项全 ✅;`kpl_client.get_daily_limit_performance` / `fetch_realtime_limit_performance` 均已封装。**依据**:接口文档(kpl-api/README.md)+ 实际下载(`/tmp/db_inventory.json` 实测)。
7. **质量与缺口**:
   - **接口调用成功**:✅ 已验证(2026-09-09 verify_live.py 21 项全通过,2026-09-15 入库 694 个交易日累计 328,406 行)
   - **行情真实性**:✅ 样本可对账(亚泰集团 2026-09-18 收 1.93 / +10.29% / 封板时间 14:33:28 与 KPL App 一致)
   - **字段检查**:✅ 22 列非空率 >99%(lu_time 在曾涨停未封板时为空,符合预期)
   - **未检验**:未做跨日连续性对账(同日 vs 隔日复盘的差值)、未做与同花顺 App 截图的像素级对账
8. **交付情况**:已通过 `get_kpl_limit_performance()` 接入 data_provider(2026-09-17 落库);**版本=截至 2026-09-18**,无凭据交付。✅ 已可被策略研究 02 调用。

### A02 · KPL 当日涨停榜/炸板榜(`tbl_cn_kpl_list`)

1. **内容与来源**:KPL 涨停/炸板快速榜单(更早生成,字段更精简)。同花顺 KPL `HomeDingPan/LimitUp`。
2. **实际存量**:`db_cn_kpl.db → tbl_cn_kpl_list`。**8,541 行,2025-09-29 起,2026-09-17 止**(注意比 A01 短,只追溯到去年 9 月底)。日频。
3. **采集范围**:**成功涨停 + 当日曾涨停但炸板的票都覆盖**(`tag='涨停' | '炸板'`,2026-09-17:涨停 49、炸板 21)。不含跌停。
4. **字段含义**:`ts_code / name / trade_date / lu_time(HH:MM:SS)/ ld_time(开板时间)/ open_time / last_time / lu_desc(涨停原因)/ tag / theme / net_change / status(首板/N 连板)/ amount / turnover_rate / free_float / lu_limit_order / limit_order / snap_ts`。**有首/末封板时间**,但**无开板次数**(那一列在 A01 里)。
5. **时间含义**:`lu_time / ld_time / last_time` 全部是字符串 HH:MM:SS(分时精度);`snap_ts` 是 T+1 拉取入库时间(看样本 snap_ts 都比 trade_date 晚一天,典型 17:02:03)。
6. **获取能力**:同上,可通过 `get_kpl_list()` / 同接口路径。**最早 2025-09-29,补历史 ≤ 1 年**(超出 KPL App 展示窗口的不一定返回)。
7. **质量与缺口**:
   - **接口调用成功**:✅ 已有 694 个交易日
   - **行情真实性**:✅ 样本字段含义一致(`status='首板' / '2连板' / ...`)
   - **缺口**:`bid_amount / bid_change / bid_turnover / lu_bid_vol / pct_chg / bid_pct_chg / rt_pct_chg` 这几列样本中**全部为空字符串**(`""`),tushare/KPL 该接口的当日实时竞买字段没有持续提供
8. **交付情况**:已通过 `get_kpl_list()` 暴露给上层。**版本=2025-09-29 ~ 2026-09-17**。

### A03 · KPL 题材及历史成员(`tbl_cn_kpl_concept_cons`)

1. **内容与来源**:每日题材的成分股名单 + 题材说明 + 热度。提供方:开盘啦,接口 `BoardConfig/GetConceptCons`(实时)/ `HisBoardConfig/GetConceptCons`(历史)。
2. **实际存量**:`db_cn_kpl.db → tbl_cn_kpl_concept_cons`。**82,531 行,2024-04-20 ~ 2026-09-18,累计 694 个交易日**。题材 ts_code 累计 268 个,题材名累计 6,287 个(同名重复累计)。TOP3 题材:AI 硬件(389 只)、立案调查(386)、关税战概念(361)。
3. **采集范围**:**全题材全成分**(每个交易日拉一次所有题材成员),不是按涨停名单筛选——所以"当日未涨停但属于题材"的票也覆盖。
4. **字段含义**:`ts_code(题材代码如 '000400.KP') / name(题材名)/ con_name(成员名)/ con_code(成员 ts_code)/ trade_date / desc(题材描述)/ hot_num(热度)/ snap_ts`。
5. **时间含义**:`trade_date`=交易日;`desc / hot_num` 是当日快照。**历史查询保留当时版本**——`snap_ts` 显示 2026-09-18 17:02:01 入库,后续若题材定义调整不会回改历史。
6. **获取能力**:可补任意交易日;**没有单独的"题材主档"表**——题材列表只能从每日的成员表反推 `DISTINCT name`(见下面 #质量缺口)。
7. **质量与缺口**:
   - **接口调用成功**:✅
   - **行情真实性**:✅ 题材→成分股关系可查
   - **缺口**:
     - **没有题材主档表**(无题材简介、创立日、所属大类等元数据);题材的"行业/大类"只通过 `theme_id` 间接关联到 801xxx 行业
     - 题材热度 `hot_num` 字段未校验是否与 KPL App 排序一致
8. **交付情况**:已通过 `get_kpl_concept_cons()` 暴露。**版本=截至 2026-09-18**。

- `first_time / last_time`:**HHMMSS 整数字符串**(例 '93212' = 09:32:12)
- `open_times`:**开板次数**(整数)
- `up_stat`:**连板统计**(字符串 'N/M')
- `limit_times`:**连板数**

### KPL `tbl_cn_kpl_list`(A02)
- `tag`:**涨停 / 炸板**
- `status`:**首板 / N连板**(字符串)
- `lu_time / ld_time`:**HH:MM:SS 字符串**

### 资金流 `tbl_cn_moneyflow`(A13)
- `buy_sm_* / sell_sm_*`:**小单**(4-10 万)
- `buy_md_* / sell_md_*`:**中单**(10-50 万)
- `buy_lg_* / sell_lg_*`:**大单**(50-100 万)
- `buy_elg_* / sell_elg_*`:**特大单**(>100 万)

### 复权因子(A23)
- **前复权价** = close × adj_factor ÷ 最新 adj_factor
- **后复权价** = close × adj_factor
